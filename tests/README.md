# Локальные тесты скилов

Запуск из корня репозитория:

```sh
python3 -B -m unittest discover -s tests -v
```

Требуются Python 3.9+, Bash и jq. Python-пакеты устанавливать не нужно.
GitHub Actions запускает эту же команду на Ubuntu с Python 3.9 при push и
pull request, затрагивающих `gws-drive/`, `gws-sheets/`, `tests/` или сам
workflow `.github/workflows/local-tests.yml`. Доступен также ручной запуск
через `workflow_dispatch`. Bash и jq устанавливаются отдельным шагом.
Облачная интеграционная проверка в CI не запускается.

Тесты не вызывают Claude, Codex, модели, настоящий gws или Google API.
Временные файлы удаляются после каждого теста. PATH изолирован: доступен
только подставной gws и необходимые локальные утилиты.

## Покрытие

- Метаданные двух SKILL.md и наличие указанных локальных ресурсов.
- Синтаксис Bash-скрипта и выполнение конкретных примеров CLI из SKILL.md
  с подставным gws: shell quoting и корректность JSON-аргументов.
- Создание tracker: название, вкладка, число колонок, буквальная запись
  заголовков, целевой sheetId, оформление первой строки, заморозка и автоширина.
- Кириллица, кавычки, переносы строк, формулы и shell-подстановки во входных данных.
- Граница 18278 колонок, некорректные заголовки, аргументы и отсутствующие зависимости.
- Восстановление через --resume без нового create, выбор вкладки, sheetId=0.
- Сбои create/get/batchUpdate, сохранение кода ошибки, сведения для восстановления.
- Повреждённые ответы API, пропущенные поля, отсутствующая/неоднозначная вкладка,
  некорректный sheetId и недостаточное количество колонок: запись не выполняется.

## Границы проверки

Большие записи разбиваются на запросы по размеру UTF-8 JSON ячеек
(до 60000 байт плюс обёртка и оформление). Тест на 18278 колонок проходит.
Есть проверки кириллицы, остановки после сбоя второго запроса и восстановления.
Одна ячейка, JSON которой превышает 60000 байт, отклоняется до создания файла.

Подставной gws проверяет JSON и фиксирует команды, но не является эмулятором
Google API и не валидирует его схему. Успешный тест примера не доказывает,
что Google примет запрос, что права доступа достаточны или что агент выберет скил.
Drive не содержит исполняемых скриптов: здесь проверяются его метаданные и
примеры, а не реальный поиск, загрузка или изменение прав.

## Интеграционная проверка Google

Отдельный явный запуск с настоящим авторизованным gws и сетью:

```sh
python3 -B tests/integration_gws.py --live
```

Без `--live` runner отказывается выполнять операции. Он проверяет доступ
до создания файлов, затем создаёт тестовую папку, текстовый файл и таблицу.
Проверяет поиск файла в папке, совпадение скачанных байтов, буквальные
заголовки (включая строку с `=`), оформление, заморозку, append двух строк
с сохранением заголовков и восстановление через `--resume` без потери строк.
В конце переносит только созданные им объекты в корзину и проверяет статус.
Не очищает корзину и не удаляет файлы навсегда.

Отчёт с командами, ответами, проверками и ID сохраняется в отдельный каталог
`test-skills/integration-*/report.json`. Можно указать новый путь через
`--report-dir PATH`. Отчёт может содержать сведения о тестовых Google-файлах,
поэтому проверьте его перед публикацией. При ошибке создания с неизвестным ID
или принудительном завершении процесса нужна ручная проверка Drive;
автоматические повторные создания не выполняются. Сбой уборки даёт ненулевой
код возврата и сохраняет ID оставшихся объектов в отчёте.

Проверки поведения агента запускаются отдельно. Ни локальный, ни интеграционный
runner не вызывает модели и не оптимизирует описания.

## Проверка выполнения инструкций агентом

`tests/agent_gws.py` запускает **один** сценарий через Codex CLI. Запуск модели
всегда явный; runner не входит в CI, не запускает Google API и не повторяет
сценарии автоматически. Требуется актуальная CLI с `--ignore-user-config`,
`--ignore-rules`, `--ephemeral` и `--json`, настроенная авторизация Codex,
Python 3.9+, Bash и jq.

```sh
python3 -B tests/agent_gws.py --run-agent --scenario drive \
  --codex /home/yarops/.local/share/pnpm/codex \
  --report-dir test-skills/agent-drive-NEW

python3 -B tests/agent_gws.py --run-agent --scenario sheets \
  --codex /home/yarops/.local/share/pnpm/codex \
  --report-dir test-skills/agent-sheets-NEW
```

Путь `--codex` в примере относится к этой машине. На другой машине укажи свою
CLI либо опусти аргумент, если `codex` из PATH сохраняет переданный CODEX_HOME.
Launcher, явно переопределяющий CODEX_HOME, отклоняется до запуска модели.
Каталог отчёта должен быть новым; существующие отчёты не перезаписываются.
Без `--run-agent` runner отказывается выполнять прогон.

Сценарии в `tests/agent_scenarios/*.json` явно вызывают скил и дают путь к
тестируемому SKILL.md. Это проверка выполнения инструкций, а не автоматического
выбора скила. Скилы копируются в `.agents/skills/` временного проекта; глобальная
установка не меняется. Подставной gws хранит состояние между командами,
разбивает список Drive на две страницы, пишет скачиваемые байты и хранит
строки и запросы оформления Sheets. Неподдерживаемые команды завершаются
ошибкой. Fake покрывает только эти сценарии, а не всю схему Google API.

Проверки обычным Python-кодом:

- Drive: авторизация до API, обе страницы списка, разрешённые команды,
  скачивание через `get` + `alt=media`, точные имена и байты двух файлов.
- Sheets: авторизация до API, успешный вызов `create_tracker.sh` в журнале
  команд агента, целевая вкладка, буквальные заголовки и строки, `RAW`,
  оформление по шаблону с sheetId=42 и тремя колонками, чтение после append.

CLI получает отдельный временный CODEX_HOME с копией только auth.json,
либо OPENAI_API_KEY из окружения. Ключ не записывается в команду/отчёт и не
передаётся окружению shell агента. Конфигурация пользователя, rules, приложения,
плагины, браузер и делегирование отключены. Для shell задаётся PATH с fake gws
и выбранными локальными утилитами; Google credentials из окружения не наследуются.
Используется workspace-write sandbox без подтверждений. Это изоляция тестовых
операций, не контейнер для недоверенного агента: sandbox допускает чтение
системных файлов; запрет чтения credentials и обхода fake задан в AGENTS.md.

Лимиты: один прогон на вызов, до 300 секунд плюс до 5 секунд завершения
процессов; модель по умолчанию gpt-6.1-sol, reasoning low. Настройки:
`--model`, `--timeout` (1..300), `--token-stop-threshold` (1..250000, по умолчанию
250000). Usage CLI приходит после завершения хода: токеновый порог **мягкий**,
не обеспечивает жёсткий предел токенов или стоимости. Он включает кешированный
вход и повторно переданный контекст. При доступном превышении runner завершает
процесс и фиксирует нарушение; при отсутствии usage число токенов неизвестно.
Для жёсткого денежного потолка нужен отдельный лимит провайдера.

В отчёте отдельно записаны `behavior_passed` (инструкции и результат),
`completed`, `stop_reason`, `token_threshold_exceeded` и общий `passed`.
Превышение порога, таймаут или незавершённый ход дают ненулевой код, даже если
конечное состояние соответствует заданию. Сохраняются prompt, команда запуска,
JSONL-события, stderr, вызовы gws, конечное состояние, скачанные файлы и SHA256
скилов/ресурсов. Временные проект, auth.json и fake удаляются после прогона;
облачных объектов для уборки нет. Отчёты остаются в игнорируемом `test-skills/`.

### Результат 2026-10-04

По одному завершённому прогону gpt-6.1-sol на сценарий. Оба прошли проверки
инструкций и фактического результата; правки скилов не потребовались.

| Сценарий | Время | Input | Cached input | Output | Поведение |
|---|---:|---:|---:|---:|---|
| Drive | 41.65 с | 98109 | 75136 | 454 | все проверки прошли |
| Sheets | 45.45 с | 107436 | 87936 | 474 | все проверки прошли |

Первоначальный мягкий порог 50000 превышен в обоих прогонах, поэтому общий
`passed` исходных отчётов — false. Это превышение учёта расхода, не ошибка
выполнения инструкций. Для будущих запусков установлен порог 250000; модели
повторно не запускались. До этих прогонов были технические отказы запуска CLI
и соединения без завершённого хода и без доступного usage.

Локальные отчёты: `test-skills/agent-drive-20261004-network/` и
`test-skills/agent-sheets-20261004/`. `assessment.json` в каждом каталоге —
повторная проверка сохранённых артефактов текущим grader без вызова модели.

Формат событий Codex: [официальная документация non-interactive mode](https://developers.openai.com/codex/noninteractive).
