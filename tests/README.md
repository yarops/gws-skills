# Локальные тесты скилов

Запуск из корня репозитория:

```sh
python3 -B -m unittest discover -s tests -v
```

Требуются Python 3.9+, Bash и jq. Python-пакеты устанавливать не нужно.
GitHub Actions запускает эту же команду на Ubuntu с Python 3.9 при push и
pull request, затрагивающих `gws-drive/`, `gws-sheets/`, `tests/` или сам
workflow `.github/workflows/local-tests.yml`. Доступен также ручной запуск
через `workflow_dispatch`. Bash и jq устанавливаются отдельным шагом.
Облачная интеграционная проверка в CI не запускается.

Тесты не вызывают Claude, Codex, модели, настоящий gws или Google API.
Временные файлы удаляются после каждого теста. PATH изолирован: доступен
только подставной gws и необходимые локальные утилиты.

## Покрытие

- Метаданные двух SKILL.md и наличие указанных локальных ресурсов.
- Синтаксис Bash-скрипта и выполнение конкретных примеров CLI из SKILL.md
  с подставным gws: shell quoting и корректность JSON-аргументов.
- Создание tracker: название, вкладка, число колонок, буквальная запись
  заголовков, целевой sheetId, оформление первой строки, заморозка и автоширина.
- Кириллица, кавычки, переносы строк, формулы и shell-подстановки во входных данных.
- Граница 18278 колонок, некорректные заголовки, аргументы и отсутствующие зависимости.
- Восстановление через --resume без нового create, выбор вкладки, sheetId=0.
- Сбои create/get/batchUpdate, сохранение кода ошибки, сведения для восстановления.
- Повреждённые ответы API, пропущенные поля, отсутствующая/неоднозначная вкладка,
  некорректный sheetId и недостаточное количество колонок: запись не выполняется.

## Границы проверки

Большие записи разбиваются на запросы по размеру UTF-8 JSON ячеек
(до 60000 байт плюс обёртка и оформление). Тест на 18278 колонок проходит.
Есть проверки кириллицы, остановки после сбоя второго запроса и восстановления.
Одна ячейка, JSON которой превышает 60000 байт, отклоняется до создания файла.

Подставной gws проверяет JSON и фиксирует команды, но не является эмулятором
Google API и не валидирует его схему. Успешный тест примера не доказывает,
что Google примет запрос, что права доступа достаточны или что агент выберет скил.
Drive не содержит исполняемых скриптов: здесь проверяются его метаданные и
примеры, а не реальный поиск, загрузка или изменение прав.

## Интеграционная проверка Google

Отдельный явный запуск с настоящим авторизованным gws и сетью:

```sh
python3 -B tests/integration_gws.py --live
```

Без `--live` runner отказывается выполнять операции. Он проверяет доступ
до создания файлов, затем создаёт тестовую папку, текстовый файл и таблицу.
Проверяет поиск файла в папке, совпадение скачанных байтов, буквальные
заголовки (включая строку с `=`), оформление, заморозку, append двух строк
с сохранением заголовков и восстановление через `--resume` без потери строк.
В конце переносит только созданные им объекты в корзину и проверяет статус.
Не очищает корзину и не удаляет файлы навсегда.

Отчёт с командами, ответами, проверками и ID сохраняется в отдельный каталог
`test-skills/integration-*/report.json`. Можно указать новый путь через
`--report-dir PATH`. Отчёт может содержать сведения о тестовых Google-файлах,
поэтому проверьте его перед публикацией. При ошибке создания с неизвестным ID
или принудительном завершении процесса нужна ручная проверка Drive;
автоматические повторные создания не выполняются. Сбой уборки даёт ненулевой
код возврата и сохраняет ID оставшихся объектов в отчёте.

Проверки поведения агента запускаются отдельно. Ни локальный, ни интеграционный
runner не вызывает модели и не оптимизирует описания.
