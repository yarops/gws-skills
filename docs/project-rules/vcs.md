# Правила работы с Git

## Сообщения коммитов

Используй формат `тип: краткое описание`.

- Тип пиши по-английски, описание — по-русски.
- Начинай описание со строчной буквы и глагола в настоящем времени, третьем лице: `добавляет`, `исправляет`, `обновляет`.
- Описывай результат изменения, а не процесс работы. Не ставь точку в конце заголовка.
- Выбирай тип по основному назначению изменения:
  - `feat` — новая возможность или расширение поведения;
  - `fix` — исправление ошибки;
  - `docs` — документация и правила проекта;
  - `test` — тесты и проверочные инструменты;
  - `ci` — конфигурация CI;
  - `refactor` — изменение реализации без изменения поведения;
  - `chore` — прочие технические изменения.
- Если нужно объяснить причину или существенное ограничение, добавь тело после пустой строки. Для простого изменения достаточно заголовка.

Примеры:

```text
feat: добавляет повторную установку и обновление скиллов с резервированием
fix: исправляет откат при сбое установки второго скилла
docs: фиксирует стиль сообщений коммитов
```

Перед коммитом проверь состав изменений и соответствие сообщения этому стилю.
Не переписывай существующие коммиты только ради оформления без явного запроса пользователя.
